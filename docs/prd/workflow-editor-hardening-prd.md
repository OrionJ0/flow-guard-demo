# PRD: 审批流程编排器可靠性与可用性增强

状态: 已实现
更新时间: 2026-06-30
适用范围: 审批场景管理、流程配置编辑器
技术基线: React + TypeScript + Vite + Ant Design + React Flow + lucide-react，mock API + localStorage 保留改动

## Problem Statement

审批配置人员现在可以在流程配置页自由拖拽节点、编辑审批节点和条件分支，但编辑器仍然像一个“可画流程的页面”，还没有达到“可信流程编排器”的标准。用户在真实配置中会遇到标签排版异常、校验信息难读、属性面板上下文不准确、流程状态含义不清、误删复杂分支风险高、连线交叉混乱、缺少撤销重做、缺少不可达节点校验、无法导出配置等问题。

这些问题会直接影响审批流程上线前的信心: 配置员不确定流程是否完整，管理员不确定启用的是哪个版本，后续开发也缺少稳定的流程 JSON 作为接口边界。

## Solution

将现有流程配置页增强为一个更可靠的审批流程编排器:

- 保持用户自由拖拽编排，不强制用户只能使用自动布局。
- 修复当前明确的 UI 问题，包括场景卡片标签高度、校验面板排版、非分支节点不显示分支属性。
- 增加流程状态生命周期，让 `草稿`、`已启用`、`有未发布变更`、`已停用` 由明确动作驱动。
- 增加导出 JSON，形成前端、mock API、未来后端之间可复用的数据契约。
- 增加撤销/重做，降低误操作成本。
- 增加图结构校验，识别孤立节点、不可达节点、无出口节点、无效分支。
- 增加复杂分支删除策略，避免删除一个条件网关时意外破坏整条审批链路。
- 增强自动布局和连线可读性，让用户可以一键整理复杂流程。

## User Stories

1. As an 审批配置员, I want 场景卡片上的风险标签保持正常高度, so that 我能快速浏览场景而不被异常布局干扰。
2. As an 审批配置员, I want 校验面板的图标、标题、描述稳定左对齐, so that 我能快速理解校验结果。
3. As an 审批配置员, I want 只有选中条件网关或分支连线时才看到分支属性, so that 我不会在普通审批节点上看到无关配置。
4. As an 审批配置员, I want 清楚知道流程当前是草稿、已启用、有未发布变更还是已停用, so that 我能判断是否需要发布。
5. As an 审批配置员, I want 通过保存、启用、停用、发布变更来改变流程状态, so that 状态变化有清晰业务含义。
6. As an 系统管理员, I want 已启用流程被编辑后自动进入有未发布变更状态, so that 我能区分线上生效版本和待发布配置。
7. As an 审批配置员, I want 一键导出当前场景和流程 JSON, so that 我可以备份、交付给后端或用于问题复现。
8. As an 前端开发者, I want 导出的 JSON 具有 schemaVersion、exportedAt、scene、workflow 等稳定字段, so that 后续可以对接真实 API。
9. As an 审批配置员, I want 可以撤销刚才的新增、删除、拖拽、属性修改和连线修改, so that 我可以安全探索流程结构。
10. As an 审批配置员, I want 可以重做被撤销的操作, so that 我能在反复调整时恢复决策。
11. As an 审批配置员, I want 使用快捷键完成撤销和重做, so that 高频编辑时不需要频繁移动鼠标。
12. As an 审批配置员, I want 编辑器校验孤立节点, so that 我不会发布画布上存在但流程不会执行的节点。
13. As an 审批配置员, I want 编辑器校验从开始节点不可达的节点, so that 我能发现断链问题。
14. As an 审批配置员, I want 编辑器校验无法到达结束节点的节点, so that 我能发现没有出口的审批路径。
15. As an 审批配置员, I want 编辑器校验分支条件缺失、分支目标缺失和优先级异常, so that 条件网关能按预期执行。
16. As an 系统管理员, I want 发布前必须通过关键校验, so that 有结构风险的流程不会被启用。
17. As an 审批配置员, I want 校验失败时画布节点也有明显标记, so that 我不只在右侧面板里找问题。
18. As an 审批配置员, I want 删除分支连线时能选择只删连线或删除该分支后续节点, so that 我可以按真实意图清理流程。
19. As an 审批配置员, I want 删除条件网关时看到影响范围确认, so that 我不会误删多个审批路径。
20. As an 审批配置员, I want 开始节点和结束节点受到保护, so that 关键流程骨架不会被误删。
21. As an 审批配置员, I want 一键整理布局, so that 复杂分支能够更清楚地分层展示。
22. As an 审批配置员, I want 连线标签、方向和分支优先级更清晰, so that 我能快速读懂审批路径。
23. As an 审批配置员, I want 自动布局不覆盖我继续手动拖拽的能力, so that 我既能快速整理也能精细调整。
24. As an 系统管理员, I want mock API 和 localStorage 持续保留配置改动, so that 页面刷新后不会丢失编辑结果。
25. As an 审批配置员, I want 可以恢复示例数据或导入备份 JSON, so that 测试数据混乱时能够回到可靠状态。
26. As an 测试人员, I want 每个增强能力都有可复现的验收路径, so that 后续迭代不会破坏流程配置核心能力。

## Implementation Decisions

- 保留当前双页面信息架构: `审批场景管理` 负责场景列表、筛选、新建、复制、删除、进入配置；`流程配置` 负责画布编排、节点属性、分支属性、校验、保存和发布。
- 保留 mock API + localStorage 作为当前数据源。后续真实 API 应复用同一数据契约，避免页面逻辑重写。
- 流程状态扩展为以下状态:

```ts
type WorkflowStatus = "草稿" | "已启用" | "有未发布变更" | "已停用";
```

- 状态不作为普通输入字段直接编辑，而由动作驱动:
  - 新建场景默认为 `草稿`。
  - 保存未启用流程保持 `草稿`。
  - 启用通过校验的草稿后变为 `已启用`。
  - 编辑已启用流程后变为 `有未发布变更`。
  - 发布变更通过校验后变为 `已启用` 并增加版本号。
  - 停用已启用流程后变为 `已停用`。
- JSON 导出以当前场景为默认范围，导出内容包含场景元信息、流程状态、版本、节点、连线、分支条件和导出时间。

```json
{
  "schemaVersion": "approval-workflow-export/v1",
  "exportedAt": "2026-06-30T00:00:00.000Z",
  "scene": {
    "id": "scene-id",
    "name": "高危数据访问",
    "tag": "高危",
    "desc": "场景描述",
    "workflow": {}
  }
}
```

- 撤销/重做在流程编辑器层实现历史栈，不污染 mock API。历史栈保存 workflow 快照，默认最多保留 50 步。
- 拖拽节点时只在拖拽结束后写入历史，避免鼠标移动产生大量历史记录。
- 文本输入、节点新增、节点删除、连线新增、连线删除、分支变更、自动布局都进入历史。
- 属性面板 tab 根据当前选择动态生成:
  - 未选择或普通节点: 显示 `节点`、`校验`。
  - 条件网关: 显示 `节点`、`分支`、`校验`。
  - 分支连线: 显示 `分支`、`校验`。
- 图结构校验以开始节点为入口做正向遍历，以结束节点为目标做反向可达判断，并输出可定位的问题列表。
- 发布和启用前必须执行关键校验。关键校验失败时阻止状态变为 `已启用`。
- 删除策略按对象类型区分:
  - 普通节点: 删除节点及其关联连线，保留起止节点保护。
  - 分支连线: 弹窗选择 `仅删除连线` 或 `删除该分支及后续节点`。
  - 条件网关: 弹窗展示影响范围，并要求用户选择保留/删除策略。
- 自动布局使用确定性的分层布局作为第一阶段，不引入重量级布局依赖。后续如果流程规模变大，再评估 ELK 或 Dagre。
- 连线增强优先使用 React Flow 的连线类型、路径参数、label 背景、命中宽度、选中态和分支优先级文案完成。
- 所有新增按钮优先使用 lucide-react 图标，并补充可访问的按钮标题或 aria-label。

## Testing Decisions

- 主要验收以外部行为为准: 用户能否看到正确状态、完成操作、得到正确导出文件、被阻止发布错误流程，而不是测试内部组件实现细节。
- 纯逻辑优先形成可测试函数: 状态流转、导出 payload、历史栈 reducer、图结构校验、分支删除影响范围、自动布局坐标计算。
- 页面级验收使用浏览器自动化覆盖关键路径:
  - 从场景管理进入流程配置。
  - 修复后的卡片标签和校验面板不溢出、不错位。
  - 普通节点不展示分支 tab，条件网关展示分支 tab。
  - 新增节点、拖拽节点、编辑属性后可撤销/重做。
  - 制造不可达节点后校验失败并阻止发布。
  - 导出 JSON 后内容包含当前场景和 workflow。
- 每次实现 issue 后至少运行 TypeScript/Vite 构建。
- 当前项目没有测试框架。如果引入单元测试，优先选择 Vitest，并保持测试集中在业务纯函数。

## Acceptance Criteria

- 场景卡片中的 `高危` 等标签不再被卡片头部撑高，移动端和桌面端都保持正常 tag 高度。
- 校验面板每一项都左对齐，长文案不会挤压图标或溢出容器。
- 选中非条件节点时，属性面板不出现 `分支` tab。
- 用户可以通过明确动作改变流程状态，而不是手动编辑状态文本。
- 用户可以导出当前场景 workflow JSON，并能在本地打开看到稳定结构。
- 用户可以撤销和重做流程编辑操作，快捷键与按钮都可用。
- 校验能发现孤立节点、不可达节点、无出口节点和关键分支配置问题。
- 发布/启用前存在关键校验失败时，页面阻止发布并给出原因。
- 删除复杂分支前必须确认删除范围。
- 自动布局后主流程、分支路径、连线标签比当前更容易阅读。
- mock API + localStorage 继续保留改动，刷新页面后流程仍存在。

## Out of Scope

- 不实现真实后端审批执行引擎。
- 不实现真实用户、角色、组织架构和权限 API。
- 不实现完整审计日志后端存储。
- 不实现多人实时协同编辑。
- 不实现服务端版本发布、回滚和灰度。
- 不强制引入 ELK、Dagre 等布局依赖，除非后续流程复杂度证明必要。
- 不把当前页面改造成低代码平台或 BPMN 全量建模器。

## Further Notes

- 本 PRD 的核心不是增加更多节点类型，而是让现有节点、分支、状态和校验可信。
- “自由拖拽”和“自动布局”不是互斥关系。自动布局是整理工具，用户仍然可以手动调整。
- JSON 导出先服务备份、联调和问题复现。导入 JSON 属于 P2 增强，可以单独排期。
- 如果后续接入真实后端，建议保留当前 mock API 接口形态，先替换 repository 实现，而不是重写页面。
